# Algo Trading

Algo Trading is a Rust project that enables algorithmic trading by providing various services for data consumption, signal generation, order management, and more. The system is designed with a modular architecture that separates concerns into distinct services, making it extensible and maintainable.

## Project Overview

This algorithmic trading system enables automated trading by consuming market data, analyzing it with various algorithms, generating trade signals, managing orders, and monitoring active trades. The system supports multiple timeframes and trading strategies, with a focus on technical analysis patterns.

## System Architecture

The project follows a modular design with clear separation of concerns:
- Each service is contained in its own directory
- Common utilities are shared across services
- The main.rs file orchestrates the system by initializing services and managing threads
- Configuration is handled through structured data types
- MongoDB is used for persistent storage
- Redis is used for high-speed data caching

## Services

### Algo Hub

The `algo_hub` service holds various algorithms that can be utilized for algorithmic trading. New algorithms can be added to this service in the future.

Currently implemented algorithms:
- Hammer Pattern detection (a bullish reversal pattern)
- Shooting Star Pattern detection (a bearish reversal pattern)

Each algorithm analyzes market data to identify specific patterns and generates trade signals when conditions are met.

### Common

The `common` service provides common utility modules that can be used across the application, including:
- `date_parser`: Utility for parsing date and time
- `enums`: Shared enums used throughout the project (TimeFrame, TradeType, MarketTrend, etc.)
- `redis_client`: Client for Redis caching
- `raw_stock`: Data structures for stock information
- `database`: Database utilities
- `utils`: General utility functions

### Data Consumer

The `data_consumer` service is responsible for consuming data from websockets and passing it to relevant functions for processing. It:
- Ingests market data from WebSocket connections (real-time data)
- Processes CSV files for historical data
- Handles different timeframes (1-minute, 3-minute, 5-minute, etc.)
- Maintains the current market state with key metrics
- Updates the database with new market information

### Order Manager

The `order_manager` service handles the placement of orders for trades based on trade signals generated by the `signal_generator`. It:
- Processes trade signals
- Creates and manages orders
- Tracks open positions
- Calculates profit/loss
- Interfaces with Redis for caching order information
- Updates the database with order status

### Signal Generator

The `signal_generator` service generates trade signals for each trade based on received ticks. The signal generation process is tailored for different trading algorithms. It:
- Analyzes processed market data
- Identifies trading opportunities based on algorithm criteria
- Generates signals with entry, stop loss, and take profit levels
- Passes signals to the order manager

### Trade Watcher

The `trade_watcher` service constantly observes placed orders. It determines the appropriate tick price to exit open orders based on target prices set. It:
- Monitors active trades
- Checks for exit conditions (stop loss or take profit)
- Closes trades when conditions are met
- Updates order status and calculates final profit/loss

### User

The `user` service manages all user-related data within the system, including:
- User authentication
- User profiles
- User permissions
- Account management

### Backtest Stock

The `backtest_stock` module provides backtesting capabilities for different timeframes:
- 1-minute data
- 5-minute data
- 15-minute data
- Daily data

This allows testing of trading strategies on historical data before deploying them in live trading.

## Technical Stack

- **Language**: Rust (2021 edition)
- **Database**: MongoDB for persistent storage
- **Caching**: Redis for high-speed data access
- **Concurrency**: Tokio for asynchronous programming and multi-threading
- **Data Formats**: CSV for historical data, WebSockets for real-time data
- **Serialization**: Serde for data serialization/deserialization
- **Visualization**: Plotters for charting

## Data Flow

1. Market data is received via WebSockets for different timeframes
2. The data is processed and stored in the current market state
3. Trading algorithms analyze the market state to identify patterns
4. When a pattern is detected, a trade signal is generated
5. The order manager processes the signal and creates an order
6. The trade watcher monitors active trades for exit conditions
7. When exit conditions are met, trades are closed and profit/loss is calculated

## Market Data & Technical Indicators

### Supported Markets

**Indices:**
- NIFTY 50
- NIFTY BANK

**Stocks:**
A wide range of Indian stocks including but not limited to:
- RELIANCE, TCS, HDFC, ICICIBANK, INFY
- SBIN, ADANIPORTS, BHARTIARTL, HINDUNILVR
- And many more (over 100 stocks supported)

### Basic Market Data

For each security, the system processes the following fundamental data points:

- **Date** - Date of observation
- **Open** - Opening price of the security on a particular day
- **High** - Highest price reached during the trading session
- **Low** - Lowest price reached during the trading session
- **Close** - Closing price of the security on a particular day
- **Volume** - Number of shares traded

### Technical Indicators

The system calculates and utilizes a comprehensive set of technical indicators for analysis:

#### Moving Averages
- **Simple Moving Average (SMA)** - Average of prices over specific periods (5, 10, 15, 20 days)
- **Exponential Moving Average (EMA)** - Weighted average giving more importance to recent prices (5, 10, 15, 20 days)
- **Triangular Moving Average (TRIMA)** - Weighted average with more weight on middle portion (5, 10, 20 days)
- **Kaufman Adaptive Moving Average (KAMA)** - Adapts to price volatility (10, 20, 30 days)
- **Hilbert Transform - Instantaneous Trendline (HT_TRENDLINE)** - Reduces noise without lag

#### Volatility Indicators
- **Bollinger Bands** - Upper, middle, and lower bands based on standard deviations
- **Average True Range (ATR)** - Measures market volatility
- **True Range (Trange)** - Maximum of price ranges for volatility measurement

#### Momentum Indicators
- **Moving Average Convergence/Divergence (MACD)** - Various combinations (5-10, 5-20, 10-20, 15-20, 12-26)
- **Relative Strength Index (RSI)** - Momentum oscillator (8 and 14 periods)
- **Momentum (MOM)** - Rate of price change (10, 15, 20 periods)
- **Rate of Change (ROC)** - Percentage price change (5, 10, 20 periods)

#### Oscillators
- **Commodity Channel Index (CCI)** - Identifies cyclical trends (5, 10, 15 periods)
- **Absolute Price Oscillator (APO)** - Difference between two EMAs
- **Percentage Price Oscillator (PPO)** - Percentage difference between two EMAs
- **Ultimate Oscillator (ULTOSC)** - Multi-timeframe momentum oscillator
- **Williams %R (WILLR)** - Identifies overbought/oversold conditions

#### Stochastic Indicators
- **Stochastic Oscillator** - Compares closing price to price range
  - Slow K and D values
  - Fast K and D values
  - Stochastic RSI K and D values

#### Trend Indicators
- **Average Directional Movement Index (ADX)** - Measures trend strength (5, 10, 20 periods)
- **Parabolic SAR (SAR)** - Identifies potential trend reversals

#### Other Indicators
- **Typical Price (TYPPRICE)** - Average of high, low, and close
- **Hilbert Transform - Dominant Cycle Period (HT_DCPERIOD)** - Estimates market cycles
- **Beta** - Measures volatility relative to the market

These technical indicators are used by the trading algorithms to identify patterns, generate signals, and make trading decisions across different timeframes.

For more detailed information on these indicators, refer to the [TA-Lib documentation](https://mrjbq7.github.io/ta-lib/).

## Getting Started

### Prerequisites

Required dependencies:
- Rust (2021 edition) - Install via [rustup](https://rustup.rs/)
- MongoDB (4.4+) - [Installation guide](https://docs.mongodb.com/manual/installation/)
- Redis (6.0+) - [Installation guide](https://redis.io/topics/quickstart)
- Tokio runtime (included in dependencies)

### Installation

1. Clone the repository:
   ```bash
   git clone https://github.com/yourusername/algo-trading.git
   cd algo-trading
   ```

2. Install Rust dependencies:
   ```bash
   cargo build
   ```

3. Start MongoDB:
   ```bash
   # Start MongoDB service
   sudo systemctl start mongod    # Linux
   brew services start mongodb-community    # macOS
   ```

4. Start Redis:
   ```bash
   # Start Redis service
   sudo systemctl start redis    # Linux
   brew services start redis    # macOS
   ```

### Configuration

1. Configure MongoDB connection:
   - The default connection string is `mongodb://localhost:27017`
   - The default database name is `algo_trading`
   - These can be modified in `src/main.rs`

2. Configure WebSocket servers:
   - The system connects to WebSocket servers for different timeframes
   - Default URLs are:
     - 1-minute data: `ws://localhost:5554`
     - 5-minute data: `ws://localhost:5556`
   - These can be modified in the `thread_worker_configs` in `src/main.rs`

## Usage

### Running the System

1. Start the main application:
   ```bash
   cargo run
   ```

2. Run in release mode for better performance:
   ```bash
   cargo run --release
   ```

3. Run with specific features:
   ```bash
   cargo run --release --features "feature_name"
   ```

### Backtesting

To run backtesting on historical data:

1. Prepare your CSV data files with historical market data
2. Update the file paths in the code (see `data_consumer_via_csv.rs`)
3. Run the backtesting module:
   ```bash
   # Example command (modify as needed)
   cargo run --bin backtest -- --timeframe 5min --strategy hammer --start-date 2023-01-01 --end-date 2023-12-31
   ```

### Monitoring

Monitor the system's performance and active trades:

1. Check MongoDB collections for trade data:
   ```bash
   # Using MongoDB shell
   mongosh
   use algo_trading
   db.orders.find({})  # View all orders
   db.trade_signals.find({})  # View all trade signals
   ```

2. Check Redis for cached data:
   ```bash
   # Using Redis CLI
   redis-cli
   KEYS *  # List all keys
   GET order:latest  # Get latest order data
   ```

3. View logs:
   ```bash
   # If using a log file
   tail -f algo_trading.log
   ```
