# Algo Trading

Algo Trading is a Rust project that enables algorithmic trading by providing various services for data consumption, signal generation, order management, and more. The system is designed with a modular architecture that separates concerns into distinct services, making it extensible and maintainable.

## Project Overview

This algorithmic trading system enables automated trading by consuming market data, analyzing it with various algorithms, generating trade signals, managing orders, and monitoring active trades. The system supports multiple timeframes and trading strategies, with a focus on technical analysis patterns.

## System Architecture

The project follows a modular design with clear separation of concerns:
- Each service is contained in its own directory
- Common utilities are shared across services
- The main.rs file orchestrates the system by initializing services and managing threads
- Configuration is handled through structured data types
- MongoDB is used for persistent storage
- Redis is used for high-speed data caching

## Services

### Algo Hub

The `algo_hub` service holds various algorithms that can be utilized for algorithmic trading. New algorithms can be added to this service in the future.

Currently implemented algorithms:
- Hammer Pattern detection (a bullish reversal pattern)
- Shooting Star Pattern detection (a bearish reversal pattern)

Each algorithm analyzes market data to identify specific patterns and generates trade signals when conditions are met.

### Common

The `common` service provides common utility modules that can be used across the application, including:
- `date_parser`: Utility for parsing date and time
- `enums`: Shared enums used throughout the project (TimeFrame, TradeType, MarketTrend, etc.)
- `redis_client`: Client for Redis caching
- `raw_stock`: Data structures for stock information
- `database`: Database utilities
- `utils`: General utility functions

### Data Consumer

The `data_consumer` service is responsible for consuming data from websockets and passing it to relevant functions for processing. It:
- Ingests market data from WebSocket connections (real-time data)
- Processes CSV files for historical data
- Handles different timeframes (1-minute, 3-minute, 5-minute, etc.)
- Maintains the current market state with key metrics
- Updates the database with new market information

### Order Manager

The `order_manager` service handles the placement of orders for trades based on trade signals generated by the `signal_generator`. It:
- Processes trade signals
- Creates and manages orders
- Tracks open positions
- Calculates profit/loss
- Interfaces with Redis for caching order information
- Updates the database with order status

### Signal Generator

The `signal_generator` service generates trade signals for each trade based on received ticks. The signal generation process is tailored for different trading algorithms. It:
- Analyzes processed market data
- Identifies trading opportunities based on algorithm criteria
- Generates signals with entry, stop loss, and take profit levels
- Passes signals to the order manager

### Trade Watcher

The `trade_watcher` service constantly observes placed orders. It determines the appropriate tick price to exit open orders based on target prices set. It:
- Monitors active trades
- Checks for exit conditions (stop loss or take profit)
- Closes trades when conditions are met
- Updates order status and calculates final profit/loss

### User

The `user` service manages all user-related data within the system, including:
- User authentication
- User profiles
- User permissions
- Account management

### Backtest Stock

The `backtest_stock` module provides backtesting capabilities for different timeframes:
- 1-minute data
- 5-minute data
- 15-minute data
- Daily data

This allows testing of trading strategies on historical data before deploying them in live trading.

## Technical Stack

- **Language**: Rust (2021 edition)
- **Database**: MongoDB for persistent storage
- **Caching**: Redis for high-speed data access
- **Concurrency**: Tokio for asynchronous programming and multi-threading
- **Data Formats**: CSV for historical data, WebSockets for real-time data
- **Serialization**: Serde for data serialization/deserialization
- **Visualization**: Plotters for charting

## Data Flow

1. Market data is received via WebSockets for different timeframes
2. The data is processed and stored in the current market state
3. Trading algorithms analyze the market state to identify patterns
4. When a pattern is detected, a trade signal is generated
5. The order manager processes the signal and creates an order
6. The trade watcher monitors active trades for exit conditions
7. When exit conditions are met, trades are closed and profit/loss is calculated
